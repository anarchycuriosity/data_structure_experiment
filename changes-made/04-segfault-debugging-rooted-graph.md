# 问题 04：段错误调试 + 有根有向图判定逻辑修复

## 问题现象

`graph_test4.cpp` 编译成功，但运行时在第 44 行触发 Segmentation Fault。程序目标是判断有向图是否存在"根"（从根出发可到达所有顶点）。

## 诊断过程

### 思维出发点

段错误（Segfault）的本质是**访问了不属于本进程的内存地址**。在 C/C++ 中，最常见的诱因有三类：

> **定理（段错误三源）**：段错误必定源于以下三者之一：
> 1. **野指针/悬垂指针** — 解引用了一个未初始化或已释放的指针
> 2. **数组越界** — 下标超出数组的实际分配范围
> 3. **栈溢出** — 通常是无限递归导致

当 IDE/GDB 报告了崩溃行号时，直接看那一行附近的**指针来源**和**循环边界**，逐个排除以上三种可能。

### 阶段 1：崩溃现场还原

崩溃行（第 44 行）：

```cpp
in_degree[cur->adjVer]++;   // cur 是野指针 → 解引用 → 段错误
```

`cur` 的赋值链回溯：

```
cur = g.VerList[i].firstEdge   (第 36 行)
     ↑
     i 来自外层循环: for (int i = 1; i <= 26; i++)   (第 31 行)
```

### 阶段 2：逐层验证

**问题 1：`g.VerList[i]` 是否有效？**

`VerList` 是 `VertexNode VerList[100]`，大小 100。`i` 遍历 1~26，数组未越界。排除数组越界。

**问题 2：`g.VerList[i].firstEdge` 是否被初始化？**

`CreateGraphFromFile` 只填充了 `VerList[1]` 到 `VerList[g.VerNum]`。dg6.grp 只有 6 个顶点，所以 `g.VerNum == 6`。

这意味着 `VerList[7]` 到 `VerList[26]` **从未被赋值**。它们是栈上的局部变量（`Graph g` 在 `main` 中声明），`firstEdge` 成员的值是**栈上的垃圾数据**。

**问题 3：垃圾数据为什么能通过 `while (cur != nullptr)` 检查？**

`nullptr` 在 64 位系统上是 `0x0000000000000000`。栈上的随机值恰好等于 0 的概率极低（约 1/2^64）。更多时候它是一个看起来像合法地址的值，于是 `while` 条件为真，进入循环体，然后 `cur->adjVer` 尝试解引用这个假地址，操作系统发现进程无权访问，发送 SIGSEGV。

### 阶段 3：根因确认

> **定理（局部变量未初始化）**：栈上的局部变量不会自动清零。其初始值是栈帧复用后残留的历史数据，具有不可预测性。

验证方法（GDB）：

```bash
g++ -std=c++17 -g graph_test4.cpp -o graph_test4.exe
gdb ./graph_test4.exe
(gdb) break 31
(gdb) run
(gdb) print g.VerNum    # 输出: 6
(gdb) continue          # 程序崩溃
(gdb) print i           # 输出: 7 （ подтверждает предположение ）
```

### 修复方案

将所有硬编码的 `26` 替换为 `g.VerNum`：

| 位置 | 原代码 | 修改 |
|------|--------|------|
| 第 31 行 | `for (int i = 1; i <= 26; i++)` | `for (int i = 1; i <= g.VerNum; i++)` |
| 第 52 行 | `for (int i = 1; i <= 26; i++)` | `for (int i = 1; i <= g.VerNum; i++)` |
| 第 65 行 | `for (int i = 1; i <= 26; i++)` | `for (int i = 1; i <= g.VerNum; i++)` |

## 延伸问题：DFS 逻辑错误

修复段错误后，DFS 还有一处逻辑 bug：

```cpp
// 错误版本
if (visited[p->adjVer] == false && p->next != nullptr)
{
    dfs(g, p->next->adjVer);   // 访问的是下一个边的目标，而不是当前边的目标
}
```

**推导**：设顶点 a 的邻接边链表为 `[b → d → nullptr]`。
- 遍历到边 b 时：`p->adjVer = b`，`p->next->adjVer = d`
- 条件成立，调用 `dfs(g, d)` — 跳过了 b，直接访问了 d

这个 bug 的后果：
1. 如果某顶点的邻接表中**最后一条边**指向一个未访问节点，该节点永远不会被访问（因为 `p->next == nullptr` 条件不满足）
2. 访问了错误的顶点，导致连通性判断结果不可预测

**正确版本：**

```cpp
if (visited[p->adjVer] == false)
{
    dfs(g, p->adjVer);   // 访问当前边指向的顶点
}
```

## dg6.grp 数据分析

### 图的拓扑结构

```
顶点: a, b, c, d, e, f（共 6 个）
边:   a→b, a→d, c→b, c→e, d→b, d→e, e→a, e→b, f→c, f→e（共 10 条）
```

### 各顶点入度

| 顶点 | 入边来源 | 入度 |
|------|----------|------|
| a | e→a | 1 |
| b | a→b, c→b, d→b, e→b | 4 |
| c | f→c | 1 |
| d | a→d | 1 |
| e | c→e, d→e, f→e | 3 |
| f | 无 | 0 |

### 有根性判定

从 f 出发的可达集：

```
f → c, e           (直接)
  → c → b          (经由 c)
  → e → a → d      (经由 e, a)
  → e → b          (经由 e)
```

从 f 可达全部 6 个顶点：**{f, c, e, a, b, d} = 全集**。

> **结论**：dg6.grp 是一个有根有向图，根为 **f**。

### 重要概念区分

当前 `judge` 函数的判定逻辑是 `root入度=0 ∧ 其他入度=1 ∧ 全连通`，这实际上判定的是**有向根树（Arborescence / Branching）**，而非一般意义上的「有根有向图」。

| 概念 | 定义 | dg6 是否满足 |
|------|------|:--:|
| 有根有向图 | 存在一个顶点可到达所有其他顶点 | ✅（根为 f） |
| 有向根树 | 根入度 0，其余入度 1，连通，无环 | ❌（b 入度为 4） |

根据你的实际需求，`judge` 函数的判定条件可能需要调整。

## 调试方法论总结

> **原则（先定位后修复）**：在修 bug 之前，必须用 GDB 或打印语句拿到「崩溃时的变量快照」。猜着改代码是效率最低的调试方式。

1. **段错误出现时**：优先怀疑循环边界和指针初始化
2. **局部变量不等于零**：全局变量编译器帮你清零，栈变量不会
3. **硬编码常量是 bug 温床**：凡是出现数字字面量（如 26），问自己「这个数字从哪里来的？能不能用已有的变量替代？」
4. **GDB 三步法**：设断点 → 跑程序 → `print` 看变量，比反复修改代码高效得多
